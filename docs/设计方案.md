# 设计方案

- 项目: Jekyll 博文 markdown 自动生成工具
- 版本: v1.5
- 日期: 2026-08-01
- 状态: Draft

配套文档: [SRS.md](./SRS.md)（需求）、[docs/adr/](./adr/)（决策记录）、[docs/glossary.md](./glossary.md)（术语）。

## 1. 概述

本设计方案基于 [SRS.md](./SRS.md) 的功能需求，描述工具的实现架构、领域模型、模块划分、关键流程与工程结构。技术栈选型见 [ADR-009](./adr/ADR-009-tech-stack.md)：.NET 10 + WinUI 3 + CommunityToolkit.Mvvm + YamlDotNet。

## 2. 系统架构

### 2.1 分层架构

采用 Clean Architecture 风格的四层划分，依赖方向自上而下：

```
┌─────────────────────────────────────────┐
│  Presentation (WinUI 3)                 │  Views + ViewModels + 绑定
├─────────────────────────────────────────┤
│  Application (用例编排)                  │  用例服务、命令、查询
├─────────────────────────────────────────┤
│  Domain (领域模型)                       │  实体、值对象、聚合根、领域服务
├─────────────────────────────────────────┤
│  Infrastructure (基础设施)               │  文件系统、YAML 读写
└─────────────────────────────────────────┘
```

- **Domain** 层不依赖任何框架，纯 C# 表达领域模型与不变量。
- **Infrastructure** 层实现 Domain 定义的仓储接口，封装 YamlDotNet 与文件 IO。
- **Application** 层编排用例（新建博文、打开博文、保存等），协调 Domain 与 Infrastructure。
- **Presentation** 层为 WinUI 3 + CommunityToolkit.Mvvm 的 ViewModel/View。

### 2.2 MVVM 绑定

- 使用 `CommunityToolkit.Mvvm` 的 `[ObservableProperty]`、`[RelayCommand]` 源生成器，最小化样板代码。
- ViewModel 依赖 Application 层用例服务，通过构造函数注入。
- View 使用 `x:Bind` 强类型绑定，提升性能。

## 3. 领域模型

### 3.1 实体与值对象

| 类型   | 名称                      | 说明                                                         |
| ------ | ------------------------- | ------------------------------------------------------------ |
| 聚合根 | `BlogProject`           | 无状态文件夹引用，含路径与子聚合访问入口                     |
| 实体   | `Author`                | 项目内作者，字段`Id`/`Name`/`Twitter`/`Url`          |
| 实体   | `Post`                  | 项目内博文，含`Filename` + `FrontMatter` + `Body` 引用 |
| 值对象 | `Category`            | 字符串值对象，0~2 个，分主/子分类                            |
| 值对象 | `Tag`                 | 字符串值对象，原样保留大小写                                 |
| 值对象 | `Slug`                | 从 title 生成的文件名片段                                    |

> v1.5 精简：`Category`/`Tag`/`Slug` 三个同构 record 合并到单一文件 `Domain/Posts/PostValueObjects.cs`。

### 3.2 聚合边界

```
BlogProject 聚合 (项目级)
├── Author[]
└── Post[]
    ├── Filename  ← 从 title/date 自动生成 (ADR-006/011)
    ├── FrontMatter
    │   ├── 强类型字段 (v1 最小集)
    │   └── UnknownFields: OrderedDictionary  ← round-trip (ADR-007)
    └── Body      ← v1.5 起工具可在"博文正文"页编辑；保存时新建写回、编辑保留磁盘最新 (FR-3.10)

工具级配置 (独立于 BlogProject)
└── DefaultProjectPath: string  ← AppData JSON (ADR-005/009)
```

### 3.3 关键不变量

- `Post.Filename` 的 date 部分必须等于 `FrontMatter.Date` 的日期部分。
- `Post.FrontMatter.Categories` 长度 ≤ 2；若长度为 2，第一个为主分类、第二个为子分类。
- `Post.FrontMatter.Authors` 0~无限，且每个 id 必须存在于当前项目的 `authors.yml`（v1.2：由"至少 1 个"放宽为"可留空"）。
- `Author.Id` 在项目内唯一。
- 输出文件编码固定为 UTF-8 无 BOM，换行符 LF（ADR-010）。
- "博文正文"页插入的图片资源目录为 `assets/img/{slug}/`，其中 `{slug}` 取自当前 Post 的文件名 slug（去日期前缀）；未保存时由 title 即时生成（ADR-006 中文保留）。

## 4. 模块设计

### 4.1 项目管理模块

- **职责**: 选择博客项目、维护项目路径、在资源管理器或 VS Code 中打开项目。
- **关键类型**:
  - `BlogProject`（聚合根，值对象化：仅 `Path` 属性）
  - `DefaultProjectSettingService`（Application）: 读写 AppData JSON 中的 `defaultProjectPath`（v1.2 内联 System.Text.Json 并移除仓储抽象；v1.5 起委托通用 `JsonFileStore` 消除 JSON I/O 重复）
  - `ProjectOpenerService`（App 层服务，v1.2 新增）: 通过 `Process.Start` 调用 `explorer.exe` 或 `code` 打开项目目录
- **UI**: 项目页展示当前项目路径，提供"选择项目路径"、"资源管理器"、"VS Code"按钮；不再进行 `_posts/` 校验（v1.2 移除 `BlogProjectValidator`，保存时由 `FilePostRepository.SaveAsync` 自动创建缺失目录）。

### 4.2 作者管理模块

- **职责**: 增删改 `authors.yml`。
- **关键类型**:
  - `Author`（实体）
  - `IAuthorRepository`（Domain 接口）/ `YamlAuthorRepository`（Infrastructure 实现，用 YamlDotNet）
  - `AuthorCrudUseCase`（Application）: v1.5 精简，失败（id 重复/不存在）时抛 `InvalidOperationException`，由 ViewModel 捕获弹窗；移除 `AuthorOperationResult` 结果类型
- **UI**: 作者列表 + 编辑面板。

### 4.3 博文管理模块

- **职责**: 新建/打开/编辑/保存博文，文件名生成，重名冲突处理。
- **关键类型**:
  - `Post`（实体）
  - `FrontMatter`（值对象，含强类型字段 + `UnknownFields` 有序字典）
  - `SlugGenerator`（Domain 服务）: 实现 ADR-006/011 的 slugify 规则
  - `FilenameConflictResolver`（Application）: 检测重名，返回三选项
  - `IPostRepository`（Domain 接口）/ `FilePostRepository`（Infrastructure）: 读写 `_posts/*.md`，front matter/body 分段读写
  - `MarkdownBodyImporter`（Infrastructure）: 剥离外部 md 文件的 front matter
  - `FrontMatterValidator`（Application 服务）: 校验必填、categories 长度、authors 存在性（v1.2 精简：内联 AuthorIdValidator 逻辑）
- **UI**: "博文头信息"页（新建/编辑表单 + 文件名预览 + 重名冲突对话框）与"博文正文"页共享同一 `PostPageViewModel` 单例（v1.5：两页不再缓存丢失，见 §8.2）。
- **PostPageViewModel 拆分**（v1.5 重构，原 700 行单体按职责拆为 partial）:
  - `PostPageViewModel.cs`（核心）: DI 字段、ObservableProperty、构造、slug 解析、防抖预览、作者加载、`FrontMatterBuilder`/`TimeZoneFormatter` 委托
  - `PostPageViewModel.Posts.cs`（CRUD）: 新建/打开/保存/加载/冲突处理
  - `PostPageViewModel.Body.cs`（正文+AI）: 导入正文/插入图片/AI 提取关键字
  - 纯函数下沉: `TimeZoneFormatter`（时区选项与 ±hh:mm 格式化）、`FrontMatterBuilder`（front matter 构造与预览，输入 `PostEditState`）、`BodyInsertion`（正文插入/追加）

### 4.4 高级功能模块（v1.3 新增，v1.5 重构）

- **职责**: 承载扩展性工具集。v1.3 曾含"插入图片"；v1.5 起图片插入移至"博文正文"模块（§4.6），高级功能页仅保留"AI 设置"卡片。
- **关键类型**:
  - `AiSettings` / `AiSettingsService` / `IAiService` / `OpenAiService`（见 §4.5）
- **UI**: 高级功能页"AI 设置"卡片（FR-7.1~7.2）+ "更多功能"占位卡片（v1.5：图片插入已移至博文正文模块 §4.6）。

### 4.5 AI 关键字提取模块（v1.4 新增）

- **职责**: 配置 OpenAI 兼容 API，并将博文正文发送给 AI 提炼关键字、替换 tags。
- **关键类型**:
  - `AiSettings`（Application record）: 持有 BaseUrl / ApiKey / Model，含 `IsConfigured` 判定。
  - `AiSettingsService`（Application）: 读写 `%APPDATA%/JekyllPostTool/ai.json`（v1.5 起委托通用 `JsonFileStore`，与 `DefaultProjectSettingService` 共享 I/O）。
  - `IAiService`（Application 端口）: `ExtractKeywordsAsync(body, maxCount)` 抽象。
  - `OpenAiService`（Infrastructure 适配器）: 基于 `HttpClient` 调用 OpenAI 兼容 Chat Completions API；每次调用读取最新配置以支持运行时修改。
- **依赖方向**: Infrastructure → Application（v1.4 新增引用，使 Infrastructure 可实现 Application 层端口 `IAiService`）。
- **UI**: 高级功能页"AI 设置"卡片（FR-7.1~7.2）；"博文头信息"页"标签"卡片"AI 提取关键字"按钮（FR-7.3~7.4）。

#### 4.5.1 提取关键字流程

```
用户在"博文头信息"页"标签"卡片点击"AI 提取关键字"
   │
   ▼
校验 Body 非空 → 否则提示"正文为空"
   │
   ▼
置 IsExtractingKeywords=true（禁用按钮，FR-7.5）
   │
   ▼
OpenAiService.ExtractKeywordsAsync(Body, maxCount=5):
   - 从 AiSettingsService 读取当前 AiSettings
   - 未配置 → 抛 InvalidOperationException（提示"未配置"）
   - POST {BaseUrl}/v1/chat/completions
       Headers: Authorization: Bearer {ApiKey}
       Body: { model, temperature:0.2,
               messages:[ {system: 提取关键字 prompt}, {user: body} ] }
   - 非 2xx → 抛异常含状态码与错误体（截断 500 字）
   ▼
解析返回 content：按 中/英文逗号、换行、顿号 分割
   - 去除序号前缀（1. / 1、 / 1:）
   - 大小写不敏感去重，保留首次大小写
   - 截取前 maxCount 个
   │
   ▼
替换 Tags = string.Join(", ", keywords)  （FR-7.4：替换）
   │
   ▼
IsExtractingKeywords=false
   │
   ▼
任何异常 → 弹"提取失败"对话框，不修改 Tags（FR-7.7）
```

#### 4.5.2 Base URL 端点拼接规则

- 以 `/chat/completions` 结尾 → 原样使用
- 包含 `/v1` → 追加 `/chat/completions`
- 其他 → 追加 `/v1/chat/completions`

### 4.6 博文正文模块（v1.5 新增）

- **职责**: 在"博文正文"页提供 markdown 正文编辑、外部正文导入与光标处图片插入。
- **关键类型**:
  - `PostPageViewModel.Body.cs`（partial）: `ImportBodyAsync` / `InsertImagesAsync` / `ExtractKeywordsAsync`
  - `ImageInserter`（Application 服务，v1.3 引入，v1.5 迁移）: 复制图片到 `assets/img/{slug}/`，返回批量 markdown 引用文本
  - `BodyInsertion`（Domain 纯函数）: `InsertAtCursor(body, text, index)`——index 为 null 或越界时追加末尾，否则在光标处插入
  - `MarkdownBodyImporter`（Infrastructure）: 剥离外部 md 文件的 front matter（FR-4.1~4.2）
- **UI**: 博文正文页（§8.2）：正文 TextBox（`x:Bind` 到 VM.Body）+ 工具栏（导入正文、替换勾选、alt 输入、插入图片）。

#### 4.6.1 插入图片流程（光标处）

```
用户在博文正文页点击"插入图片..." → FileOpenPicker 多选 → 源图片路径列表
   │
   ▼
CanInsertImages 判定: 已选项目 且 slug 可确定
   - 已保存: slug = ImageInserter.ExtractSlugFromFileName(_originalFilePath)（去日期前缀）
   - 未保存: slug = SlugGenerator.Generate(Title)（ADR-006 中文保留；标题为空则禁用按钮）
   │
   ▼
目标目录 = {BlogProject.Path}/assets/img/{slug}/
Directory.CreateDirectory(targetDir) (若不存在)
   │
   ▼
ImageInserter.InsertAsync: foreach 源图片
   - 目标文件名 = 原文件名
   - 若目标路径已存在，追加 -1, -2, ... 直到可用
   - File.Copy(src, dest) (不覆盖)
   - markdown += $"![{alt}](/assets/img/{slug}/{dest-filename})\n"
   │
   ▼
Body = BodyInsertion.InsertAtCursor(Body, markdown, 光标位置)   ← 光标处插入（v1.5）
   │
   ▼
光标位置取自正文 TextBox.SelectionStart；为 null/越界时追加末尾
```

> v1.5 变更：插入动作改为**内存中**修改 `VM.Body`（不再立即改磁盘文件），随下一次保存统一写入；编辑已有博文时正文仍遵循 FR-3.10 保留磁盘最新 body。

## 5. 关键流程

### 5.1 新建博文流程

```
用户填写表单
   │
   ▼
ViewModel 收集字段 → 构造 FrontMatter (强类型 + 空 UnknownFields)
   │
   ▼
SlugGenerator.Generate(title) → Slug
Filename = $"{date:yyyy-MM-dd}-{slug}.md"
   │
   ▼
文件名作为预览展示，随 title 实时更新
   │
   ▼
保存命令 → 全量校验 → FilenameConflictResolver.Check(_posts/, filename)
   │
   ├─ 无冲突 → 写文件
   ├─ 有冲突 → 弹对话框 (改title / 加序号 / 覆盖)
   │            └─ 用户选择后 → 写文件
   ▼
FilePostRepository.Save: 重组 front matter YAML + 内存 Body（v1.5：新建时正文与 front matter 一次写入）
   │
   ▼
刷新当前项目状态
```

### 5.2 打开已有博文流程

```
用户点击"打开已有博文"或拖放 .md 文件
   │
   ▼
校验文件是否属于当前项目 _posts/（拖放时额外校验）
   │
   ▼
FilePostRepository.Load(path)
   │
   ├─ 读取文件全文
   ├─ 切分: 首个 --- 块 = front matter; 其余 = body
   ├─ YamlDotNet 解析 front matter → 有序字典
   ├─ 已知字段映射到 FrontMatter 强类型
   ├─ 若存在单数字段 author，自动迁移为 authors 数组
   └─ 其余存入 UnknownFields
   │
   ▼
ViewModel 填充表单 (强类型字段可编辑; UnknownFields 不展示)
   │
   ▼
用户编辑 → 保存 (见 5.4)
```

### 5.3 导入正文流程

```
用户在"博文正文"页点击"导入正文" → 选择外部 .md 文件
   │
   ▼
MarkdownBodyImporter.Import(path)
   │
   ├─ 读取文件
   ├─ 若以 --- 开头: 切到第二个 --- 之后为 body
   ├─ 否则: 整文为 body
   └─ 返回 body 字符串 (忽略其 front matter)
   │
   ▼
默认追加到 VM.Body 末尾；UI 提供"替换"选项（ReplaceBodyOnImport）
   │
   ▼
随下一次保存统一写回（新建时写入；编辑已有博文时保留磁盘最新 body，见 §5.4）
```

### 5.4 保存与冲突处理

```
保存命令触发
   │
   ▼
重新读取磁盘上当前文件，检查最后修改时间/内容哈希
   │
   ├─ 与打开时一致 → 继续
   └─ 已变更 → 弹窗提示用户，询问是否继续覆盖
   │
   ▼
全量校验（必填、格式、authors 存在性、categories 长度）
   │
   ▼
合并策略:
   - front matter 段: 用表单值 + UnknownFields 重组
   - body 段: 用磁盘最新 body（可能含插入图片追加的引用）
   │
   ▼
File.WriteAllTextAsync (UTF-8 无 BOM, LF)
   │
   ▼
成功 → 更新缓存; 失败 → 提示
```

> 关键设计（v1.5 更新）: 
> - **新建博文**：`PostCreateUseCase.CreateAsync(project, frontMatter, body)` 将内存正文与 front matter 一次写入。
> - **编辑已有博文**：工具不缓存正文，保存时总是取磁盘最新 body、仅替换 front matter 段（FR-3.10）。外部编辑器修改正文不会被覆盖；若外部修改了 front matter，则会被表单值覆盖，因此保存前会检测并提示用户。
> - 正文页的导入/插入图片（v1.5）在**内存** `VM.Body` 中生效，随下一次保存按上述规则写回。

### 7.1 项目依赖方向

```
App → Application → Domain
        │  ▲           ▲
        │  │           │
        ▼  └───────────┘
   Infrastructure ──→ Domain
        │
        └──→ Application (v1.4：实现 IAiService 端口)
```

- Domain 不引用任何上层。
- Application 引用 Domain，不引用 Infrastructure（通过接口反转）。
- Infrastructure 引用 Domain + Application（v1.4：实现 `IAiService`）+ YamlDotNet。
- App 引用 Application + Infrastructure（用于 DI 注册）+ WinUI 3。

## 8. UI 设计要点

### 8.1 导航结构

- 左侧导航：项目 → 作者 → 博文头信息 → 博文正文 → 高级功能 五大区域（v1.3 新增"高级功能"，v1.5 将原"博文"页拆分/重命名为"博文头信息"与"博文正文"两个独立导航项）。
- 选中项目后，作者、博文头信息、博文正文与高级功能区域才可用。
- 博文头信息/博文正文区域无列表页，直接进入新建/编辑状态；两页共享同一 `PostPageViewModel` 单例（`NavigationCacheMode=Required`，v1.5 修复切换页面状态丢失）。
- 未打开/未保存博文时，"博文正文"页仅正文编辑可用；插入图片按钮按 `CanInsertImages` 禁用（未选项目或标题为空）。

## 9. 持久化设计

### 9.1 AppData JSON

`DefaultProjectSettingService` 与 `AiSettingsService` 均委托通用 `JsonFileStore`（v1.5 新增）：`ReadAsync<T>`（文件不存在返回 default）/ `WriteAsync<T>`（自动创建目录、CamelCase、缩进 2 空格），消除两处重复的 JSON I/O 逻辑。

```json
// %APPDATA%\JekyllPostTool\settings.json
{
  "defaultProjectPath": "C:\\Users\\dioha\\OneDrive\\文档\\self-exiler.github.io"
}
```

### 9.2 authors.yml 读写

- 使用 YamlDotNet 的 `Deserializer` + `Serializer` 配合 `OrderedDictionary`/自定义类型，保留键顺序与注释。
- 写回时保持 id 作为 YAML 键的映射结构。

### 9.3 博文文件读写

- 读: `File.ReadAllText`（按 UTF-8）→ 切分 front matter/body → YamlDotNet 解析 front matter。
- 写: 重组 front matter YAML + 磁盘最新 body → `File.WriteAllTextAsync`（UTF-8 无 BOM，LF）。
- front matter 序列化顺序: 强类型字段在前（title, date, categories, tags, authors, description），未知字段按原顺序追加。

### 9.4 图片资源（v1.3 新增，v1.5 光标处插入）

- 路径: `{BlogProject.Path}/assets/img/{slug}/{filename}`
- 复制方式: `File.Copy`（不覆盖），文件名冲突自动追加 `-1`/`-2` 序号
- markdown 引用: `![alt](/assets/img/{slug}/{filename})`，插入到正文**光标处**（`BodyInsertion.InsertAtCursor`，v1.5 由"追加到正文末尾"改为光标处；无光标/越界时追加末尾）

## 10. 错误处理策略

| 场景                       | 策略                                                  |
| -------------------------- | ----------------------------------------------------- |
| 项目路径不存在/无权限      | 阻断 + 提示；若默认路径失效则静默清空设置并回到选择页 |
| `authors.yml` 格式错误   | 提示具体行号，提供"打开原文件"入口，不强行解析      |
| 博文 front matter 格式错误 | 同上，保留原文不破坏                                  |
| 保存时磁盘文件被外部修改   | 弹窗提示并询问是否继续覆盖                            |
| 保存时磁盘文件被删除       | 提示文件不存在，询问是否新建                          |
| 保存时 IO 异常             | 提示并保持原文件不变                                  |
| 插入图片时源文件不可读     | 跳过该图片，继续处理其他图片，结束后提示跳过数量      |
| 插入图片时目标目录无写权限 | 阻断 + 提示，不复制任何文件                          |
